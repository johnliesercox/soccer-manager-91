# Soccer Manager '91

A phone-first football management game in the spirit of the 1991 Amiga originals. The playable game is one HTML file (`index.html`) plus a manifest, a service worker and two icons; everything else in this repository is the source it is built from.

Live at https://johnliesercox.github.io/soccer-manager-91/

## Rebuilding after a change

```
python3 build.py
```

That rewrites `index.html` (and `soccer-manager-91.html`). From 1.6.0 the plain command is the release build: style E alone,
the painted art, about 7.1 MB. `ISO_STYLES=B python3 build.py` makes the 1.5.0 look; `ISO_STYLES=B,E ISO_DEFAULT=E` a
review build with both (the View button then offers the other style). Nothing but `ISO_STYLES` and `ISO_DEFAULT` changes
what the build contains. To run the tests (Node 18 or later; the first time run `npm install` to fetch the headless canvas and DOM):

```
node test-matchday.js
node test-playback.js
node test-matchday-ui.js
node test-phase25.js
node test-isometric.js
node test-highlights.js
node test-contact.js
node test-camera.js
node test-record.js
node test-restarts.js
node test-contracts.js
node test-hof.js          # needs a copy of the built game at /tmp/sm91-ladder-test.html (cp soccer-manager-91.html /tmp/sm91-ladder-test.html)
node test-youth.js
node test-equivalence.js
node test-regression.js
node test-deadball.js
node test-locomotion.js
node test-touch.js
node test-situations.js    # two seasons of extra time, shoot-outs, dismissals and kit colours (about a minute and a half)
node test-ahead.js         # painting the ground ahead of a cut (about a minute and a half)
node test-smooth.js        # tiles and player pictures made the cheap way are the same pixels; work ahead is spread over frames (about a minute and a half)
node test-tactics.js       # match plans and the rebalanced formations: identical to 1.7.1 when everyone is all-Balanced or the rules are off, whose plan is used, saves, the computer managers' rule, and the quick balance bench
node test-style.js         # the match pictures leaning with the plans (slice 3, stage A): identical to the 1.7.1 builder with the default plan on both sides, every goal the same goal as with no lean, the established actions still drawn, the agreed differences between styles, possession by time on the ball (about ten minutes)
node test-tactics-ui.js    # the tactics screens: the Match plan card and what it says against what the engine does, Home, the figures after a match, phone width, hot-seat, old saves, the 1.7.1 rules switch
```

The balance bench for tactics and formations, which measures the game's own match code (`Engine.matchModel` and `Engine.playMatch`), not a copy of its rules:

```
node tools/tactics-balance.js                              # formations, each control, all 81 plans against all 81 (about two minutes); exits 1 if a balance target is missed
node tools/tactics-balance.js --play --league              # also 100,000 matches really played, and the league's shape over 24 seasons, 1.7.1 rules against the rules now (about ten minutes)
node tools/tactics-balance.js --only none --worth          # what tactics are worth in all over a 30-match season against the computer clubs: the best plan left on, the best chosen match by match, the worst (two minutes)
node tools/tactics-balance.js --only none --seasons 1000 --physio 0,1,2,3      # whole seasons with one setting left on (long: about three minutes a line)
node tools/tactics-balance.js --only none --seasons 1000 --no-singles --plans "1,-1,1,1;1,1,1,-1@4-3-3" --formations      # whole plans (mentality, passing, pressing, shooting as -1, 0, 1) and formations left on
node tools/tactics-balance.js --set '{"ATT_UP":0.12}'     # try a value without editing the engine
```

What the match pictures show, set beside the plan each side played (the measurement for slice 3 of the tactics milestone; it changes nothing). `--force "m,p,r,s/m,p,r,s"` draws every match to the two plans given (home/away; each number is -1, 0 or 1 for mentality, passing, pressing, shooting), and `--plain` draws with no lean:

```
node tools/highlight-style.js                  # three seasons, every side: passes in a spell and their length, where the ball is won, where shots are struck from, the ball as drawn against the engine's possession (about half a minute)
node tools/highlight-style.js --worlds 6 --out file.json
SM91_STYLE="0,1,-1,1/0,-1,1,-1" node -r ./tools/style-preload.js test-contact.js   # any matchday suite again with every match drawn to two forced plans (the style sweep)
```

The numbers that set how strong each control is are the `TACTICS` block near the top of `engine.js`; change one, run the bench. Opening the game with `?rules=1.7` on the address plays by the match rules of 1.7.1 (no plans, the old formation values): the comparison tools use it to show that nothing but the match rules has moved (`SM91_QUERY='?rules=1.7' node tools/frame-reference.js . out.json tools/reference/frames-1.7.1.json`, and `node tools/ui-parity.js <site> <out> '?rules=1.7'`).

To look at a particular match again, open the game with `?seed=1991&club=3` on the address (the same seed and club index give the same season every time) and, if you want, `&t=1640` to open the first match watched at that match second. In the match, with a keyboard, `,` and `.` step fifteen seconds back and forward, and `g`, `c`, `k`, `h`, `w` jump to five seconds before the next goal, card, save, header or volley, or shot against the woodwork (`s` still skips to the next highlight, space pauses, `1`, `2`, `4` set the speed).

To re-render the generated isometric art (about six minutes for both styles at three scales): `node tools/iso-art.js --style both --spr 24,16,12`, then `python3 tools/iso_pack.py assets/matchday/isometric/B`. The painted sheets and textures are converted from the Floyo outputs with `tools/iso_paint.py` (see `tools/floyo/README.md`); re-rendering the generator does not touch them.

Frame pacing on a phone, between measurements on a real one (these need Playwright and a built game):

```
node tools/phone-probe.js . 6 out.json        # a minute of play at the size of a Galaxy S23 Ultra with the processor slowed six times; fails if more than 1% of frames are slower than 30 a second
node tools/tile-reference.js . out.json tools/reference/ground-tiles-before-smoothness-pass.json         # every ground tile, pixel for pixel
node tools/sprite-reference.js . out.json tools/reference/player-pictures-1.7.1.json                     # 61,248 player pictures, pixel for pixel
node tools/frame-reference.js . out.json tools/reference/frames-1.7.1.json                               # 198 whole frames of one match, pixel for pixel
node tools/hair-audit.js .                                                                              # the hair audit: all 5,568 player pictures as the game draws them, and every player's look through 20 seeded matches (about eight minutes; --matches 0 for the pictures alone, about a minute)
python3 tools/test_iso_paint_hair.py                                                                    # the converter's hair rule, on a made-up painting (a second)
```

The hair audit and the converter's test are part of the standard set from 1.7.1 (John's instruction, 19 November 2026): run them at every checkpoint and release, and after any change to the painted sheets, the converter, the palette or the recolouring. The player pictures and the frames were recorded again at 1.7.1, because that release changed the pictures on purpose (hair stored as hair): with the old sheets the new code draws all 198 frames and all 61,248 pictures exactly as 1.7.0 did, and in the sheets every changed pixel is hair before or after (`HAIR-FIX-1.7.1.md`). The ground tiles' reference is still the one from before the smoothness pass.

The three reference files were taken from the build before the phone smoothness pass of 17 November 2026, so a change to how the ground is painted or a player's picture is recoloured that alters a single pixel shows up. A change that is meant to alter the picture needs new reference files (run the tool without the last argument and keep its output).

Each prints a final "PASSED" or "errors: none" line. `test-equivalence.js` and `test-record.js` compare the engine with the frozen copies in `legacy/` (`engine.v112.js`, `engine.v150.js`), so that folder has to be present. From the tactics milestone they make that comparison with the new match rules switched off (`CFG.TACTICS.on = false`), and `test-tactics.js` proves against `legacy/engine.v171.js` that "off" is the 1.7.1 engine exactly. `test-camera.js` likewise plays its twelve sample matches by the 1.7.1 rules, because its limits were set on that sample (see `TACTICS-SLICE-1.md`, section 7); it now always prints, for each screen size, the two figures the phone camera sits near its limit on (frames with no player in view, and both posts in view when a shot arrives), which is what the camera measurement of `TACTICS-SLICE-3-STAGE-A.md` is made from. `test-style.js` compares the timeline builder with the frozen copy of it in `legacy/matchday-1.7.1/`, so that folder has to be present too. Three suites had an assumption corrected at Stage A of slice 3, each with a note in the file saying what and why: `test-restarts.js` (a corner awarded in the last seconds of a half is not always taken), `test-touch.js` (a figure with nobody near it means nobody, including one half off the stage) and `test-highlights.js` (a woodwork strike with no time left for the rebound, and a goal kick lost before it is taken when a booking is due, are counted apart and held rare). All four things are in the 1.7.1 pictures too; the samples did not happen to hold them until the pictures of those matches were drawn differently.

## Putting it online with GitHub Pages

1. Create a repository called `soccer-manager-91`.
2. Upload the contents of this folder (**Add file > Upload files**, drag everything in) and commit.
3. **Settings > Pages**: Source "Deploy from a branch", branch `main`, folder `/ (root)`. Save. The URL appears after a minute.

Open it on your phone. In Safari tap Share > **Add to Home Screen**; in Chrome on Android use the menu > **Add to Home screen**. It then opens full screen, works offline, and saves live in the browser on that phone.

## Releasing an update

1. Set `APP_VERSION` in `ui.html` and add the release's entry at the top of `CHANGELOG` (the What's new screen), set `VERSION` in `sw.js` to `sm91-v<version>`, run `python3 build.py`.
2. Run the suites (the list above) and `node tools/save-compat.js legacy/release-1.6.0 .` (the folder of the last release), which plays games on the last release and resumes them on the new build. `node tools/viewport-audit.js . out` watches a match in the Isometric view at the five viewport sizes of the Phase 3 brief and checks controls, touch selection, turning the phone in every state, full time after Skip and the goal badge, with screenshots. `node tools/soak-audit.js . out [part]` drives the game through what only shows over time or when something breaks: ten matches for leaks, the isometric view made to fail four ways, one visit then no network, a three-manager hot-seat week, the measuring screen, and stills of the rare situations (all three tools need playwright).
3. Tag the commit that is live before uploading anything (GitHub: Releases, "Draft a new release", a new tag such as `v1.6.0` on `main`), so there is always a named copy to go back to, and copy the live `index.html`, `sw.js`, manifest and icons into `legacy/release-<version>/` for the same reason. `ROLLBACK.md` says how.
4. Upload the new files over the old ones (same drag and drop) and commit. Players get the new version the next time they open the game online; their saves carry over because the game migrates old save formats and never clears storage. The `VERSION` string in `sw.js` makes installed phones refresh their offline copy too.

## Feedback link

In `ui.html`, near the top of the script, set `const FEEDBACK_URL = '';` to a Google Form link and a "Send feedback" button appears on the title screen (then rebuild).

## Version history

* **1.7.1: the hair fix. Approved on `milestone-0-hair`, not deployed (John's decision, 19 November 2026).** A player's hair no longer changes colour as he moves: the painted sheets had much of the hair stored as boots or eye (always drawn black) and brown shadows on legs and arms stored as hair; `tools/hair_repair.py` corrects the six sheets, `tools/iso_paint.py` no longer makes the mistake, and `tools/hair-audit.js` checks every picture as the game draws it. Also found by the audit and fixed: a one-frame pose asked for with the running stride's frame was drawn as the generated figure instead of the painted one. Known limitation: the keepers' sheet has one hairstyle. `HAIR-FIX-1.7.1.md`.
* **1.7 (Phase 3, Milestones 4 and 5): touch, layout, and holding up. Ready, not deployed** (see "Where things stand" at the top). The phone smoothness pass (after the first measurement on a real phone): a ground tile paints only what lies inside it and, ahead of need, a layer a frame; player pictures are written from a one-byte-a-pixel copy of their sheets and made before the frames that show them; the match screen tells the view of goals and cuts by one rule (`MD.lookAhead`) that the tests share. No pixel changed (`tools/tile-reference.js`, `tools/sprite-reference.js`, `tools/frame-reference.js`). Milestone 5: ends change in extra time (`MD.homeDirAt`); kit clashes count both colours of a patterned shirt, and keepers and the referee are dressed per match to stand apart (`kitsFor` in `renderers/iso-actors.js`); a view that fails gives way to Pixels and the match carries on; the scale and the ground of the next cut are worked out ahead of it (`prepare`, `planJob`); a measuring screen for real-phone frame rates (What's new). `test-situations.js`, `test-ahead.js` and `tools/soak-audit.js` keep it. Milestone 4: Selecting a player by touch with a fingertip's tolerance and the tapped man winning in a crowd (`pick` in `renderers/isometric.js`), a tag with number, name and position; the stage redrawn complete when the phone is turned while paused, at full time and after Skip; 44 px match buttons on a phone held upright; the generated crowd still under reduced motion. `test-touch.js`, `test-camera.js` at the five real stage sizes and `tools/viewport-audit.js` keep it. Phone landscape is unchanged and recorded as open.
* **1.6 (Phase 3, Option E): painted matchday.** Blender figures and ground painted through Floyo (Qwen Image 2512 with the Fun ControlNet Union, depth map only) as style E: every pose and frame in three hair styles, keepers and referee, painted stands, terraces and corners with a modelled crowd, Blender goals with sagging nets, a shadow and a net that bulges on a goal. Dead balls behind the goal line give goal kicks and corners; players run when they move. `test-deadball.js` and `test-locomotion.js` keep both. `PHASE-3-ARCHITECTURE.md` and `PHASE-3-OPTION-E-CHECKPOINT.md` are the record.
* **1.5 (Phase 3): isometric matchday.** The raised-corner view with painted stands, dugouts and boards, highlights chosen for variety, emotion and commentary.
* **1.4 (Phase 2.5): believable football.** A deterministic role planner (`src/matchday/behaviour.js`), bounded trajectories in metres per second (`trajectories.js`) and explicit ball-action beats (`interactions.js`) feed the shared scene that every renderer draws. Results are untouched. Desktop two-column match screen. `ARCHITECTURE_MATCHDAY.md` carries the Phase 3 handover contract.
* **1.3: pixel stadium.** Pixel-art players generated in code and recoloured per kit, a referee, stands and a crowd, with a camera that follows the ball.
* **1.2: matchday.** Watch your match on an animated top-down pitch, or take the instant result. The viewer never changes a result.
* **1.1.** Contracts and morale, bookings and suspensions, the youth academy, club records and the hall of fame, challenge starts, and a shared ladder (needs the worker). Saves are compressed so that eight named saves fit.

## Notes

* Saves are stored in the browser on that phone (localStorage). Clearing site data clears them. The in-game Saves screen keeps up to eight named copies.
* Club and competition names are the real 1991 ones. If the game ever grows beyond a hobby release, swap them for fictional ones; the rename screen already exists for this.
